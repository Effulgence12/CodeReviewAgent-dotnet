# .NET 应用安全规范

安全审查关注信任边界：来自用户、文件、网络、消息和配置的输入都应先验证，再进入敏感操作。

## 输入、路径与注入

- 在边界验证类型、长度、范围、格式和允许值；验证失败应尽早返回明确错误。
- 文件路径必须绑定到允许的根目录，拒绝绝对路径、`..` 路径穿越、符号链接绕过和同前缀兄弟目录。
- SQL、命令、模板和日志字段使用参数化 API，不要把不可信字符串拼接成可执行内容。
- 反序列化只接受预期类型和受控大小，避免开启危险的多态类型解析。

## 密钥与敏感数据

- API Key、密码、令牌和连接字符串不得硬编码或提交仓库；使用环境变量、用户机密或密钥管理服务。
- 不在异常、日志、追踪、测试快照或 Agent Observation 中输出秘密和完整敏感载荷。
- 比较和存储凭据使用平台安全 API；密码使用专门的慢哈希，不使用普通 SHA 哈希。

## 权限与外部访问

- 使用最小权限：文件写入、数据库账户和外部令牌只授予当前操作需要的能力。
- 服务端不能仅因客户端传入路径、URL 或对象 ID 就信任其所有权；必须重新授权。
- 对外部 URL 做协议和目标限制，防止 SSRF；设置超时、取消和响应大小上限。

## 安全失败

认证失败、输入非法和策略拒绝不应自动重试。错误响应避免泄露内部路径、堆栈和账户存在性，同时在受保护日志中保留可调查的关联标识。

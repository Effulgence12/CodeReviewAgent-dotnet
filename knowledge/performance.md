# .NET 性能规范

性能优化应从可复现的测量开始。先确定延迟、吞吐、CPU、分配或 I/O 中真正受约束的指标，再修改热点代码。

## 热路径与分配

- 使用 BenchmarkDotNet、Profiler 和生产指标定位热路径，不凭直觉微调冷代码。
- 避免在高频循环中重复创建临时集合、闭包、正则表达式和大字符串。
- 已知容量时为 `List<T>`、`Dictionary<TKey,TValue>` 和缓冲区设置合理初始容量。
- 对象池和 `Span<T>` 会增加复杂度，只在测量证明收益且生命周期安全时采用。

## 集合与 LINQ

- 选择符合访问模式的集合：按键查找优先字典，成员判断可考虑集合，顺序遍历优先连续存储。
- 避免对同一个延迟 LINQ 查询重复枚举；需要复用结果时明确物化一次。
- 在热点循环中检查多层 LINQ、排序和 `Count()` 是否产生多次遍历或额外分配，但不要为消除 LINQ 牺牲普通路径可读性。
- 合并数据库或远程查询，避免 N+1 I/O。

## 字符串、I/O 与异步

- 少量字符串拼接使用插值即可；循环内大量拼接使用 `StringBuilder` 或流式写入。
- 大文件和响应采用流式处理，设置缓冲区、取消和大小上限，避免一次性载入全部内存。
- I/O 密集操作使用异步 API；CPU 密集工作应控制并行度，避免无界创建任务。

## 缓存与验证

缓存必须定义容量、过期、一致性和击穿策略。优化后重新运行相同基准，并关注 P95/P99、GC 暂停和内存峰值，确认没有用平均值掩盖尾延迟回退。

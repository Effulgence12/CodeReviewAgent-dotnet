# CodeReviewAgent · 开发计划书

> .NET 程序设计课程期末项目 —— 基于 .NET 的 AI 代码审查 Agent
> 三人小组（组员 A / B / C）协作开发。本文件是面向全组的开发蓝图：明确架构、分工、接口契约、里程碑与交付物。

---

## 1. 项目目标

开发一个能够**自主推理、规划并调用工具**完成 C#/.NET 代码审查的 AI Agent。系统以**一个对话式编排 Agent** 为中心：它由 LLM 驱动、拥有对话记忆与一个工具箱，能与用户多轮交互，并**动态决定**每一步是直接回答、调用某个细粒度工具，还是触发一次**多 Agent 深度审查**（评审 → 汇总 → 修复验证三阶段）。对外通过 **Web 聊天界面**供人使用，并通过 **MCP 服务端**把核心能力暴露给其它 AI 客户端。

### 必须达成的核心要素（课程基础要求）

- C# / .NET 8+
- 通过 API 调用大模型（OpenAI 兼容端点）
- 手写 **ReAct 推理循环**（Thought → Action → Observation，带最大步数上限）
- **≥3 个自定义工具**（本项目规划 5 个）
- **记忆机制**（对话/工作记忆维持上下文）
- 用户交互界面（Web）
- 正确的 `async/await`、错误处理、日志、DI、配置系统

### 进阶要素（加分）

- 多 Agent 协作
- RAG 向量检索接入外部知识库
- MCP 服务端
- 流式输出 / 推理可观测性
- 单元测试

## 3. 总体架构

### 3.1 整体结构

```
final/
├─ src/
│  ├─ CodeReviewAgent.Core/   # 核心类库：ReAct 循环、记忆、工具、RAG、编排（不可单独运行）
│  ├─ CodeReviewAgent.Web/    # Blazor 聊天界面（唯一交互前端）
│  └─ CodeReviewAgent.Mcp/    # MCP stdio 服务端（对外暴露能力）
├─ tests/CodeReviewAgent.Tests/  # xUnit 单元测试
├─ knowledge/                 # RAG 知识库语料（编码规范）
├─ samples/                   # 含缺陷的示例代码（演示/测试）
├─ docs/                      # 架构文档 + 反思报告 + 本计划
└─ README.md
```

依赖方向单一：`Web` 与 `Mcp` 均只依赖 `Core`，彼此不互调。

### 3.2 运行时架构（两层编排，嵌套而非平铺）

```
用户（Web 聊天） / 外部 MCP 客户端
        │
        ▼
┌────────────────────────────────────────────────────────┐
│ 对话式编排 Agent（LLM 驱动 · 带记忆 + 工具箱）           │  ← 唯一入口；由 LLM 动态决定每一步
│   细粒度工具：read_file / list_files / analyze_code      │
│              search_standards / propose_fix /            │
│              compile_check                                │
│   粗粒度动作：run_deep_review   ──┐（整包多视角评审）     │
│              run_remediation   ──┤（整包修复 + 验证）     │
└───────────────────────────────────┼────────────────────┘
                                    ▼
   ┌───────────────────────────────────────────────────┐
   │ 多 Agent 深度审查（固定工作流，被当作动作触发）      │
   │  阶段1 评审：风格Agent ∥ 安全Agent ∥ 性能Agent      │ ← 各自独立 ReAct 循环 + 工作记忆，循环内调工具
   │  阶段2 汇总：主审 Agent 合并 / 去重 / 按严重度排序   │
   │  阶段3 修复（可选）：修复 Agent 取已确认发现         │
   │           → propose_fix 生成补丁 → compile_check 验证 │
   └───────────────────────────────────────────────────┘
```

要点：
- **两层编排，职责不同**：顶层对话 Agent 是 **LLM 驱动的动态规划者**（每轮决定答 / 调工具 / 触发整包动作）；底层深度审查是**固定工作流**（全面审查时三视角恒定，结构已知，无需动态规划）。
- **角色按「判断维度」分，工具按「能力」分**：风格 / 安全 / 性能 / 修复是需要 LLM 判断的**角色（Agent）**；编译是确定性的 `compile_check`**工具**——不设「编译专家」。
- **不区分单/多 Agent 模式**。系统只有一个对话 Agent；多 Agent 是它的动作之一，被「用起来」而非孤立存在。
- 四大要素（推理循环 / 工具 / 记忆 / 多 Agent）在同一条交互流里**组合咬合**。

## 4. 接口契约（务必先行确认，保证并行开发）

为让三人并行，第一阶段先冻结以下公共契约（由组员 A 在 `Core` 中定义为接口/抽象，B、C 面向接口开发，互不阻塞）：

```csharp
// 1) 工具插件契约：每个工具是一个带 [KernelFunction] 方法的类，沙箱绑定到审查根目录
//    约定构造签名 (string rootDirectory[, 依赖服务...])，方法参数/返回均为可序列化类型。

// 2) 推理可观测：Agent 每一步把事件推给观察者，供 Web 实时渲染、测试断言
public interface IAgentObserver
{
    void OnStep(string agent, string kind /*step|thought|action|observation|final*/, string text);
}

// 3) 记忆：维持一段对话/工作上下文，支持超预算时的摘要压缩
public interface IConversationMemory
{
    void AddUser(string text); void AddAssistant(string text); void AddToolResult(string text);
    IReadOnlyList<ChatMessage> Snapshot();
}

// 4) Agent 公共 API：交互式多轮 + 一次性任务两种调用，返回结构化结果
public interface IReviewAgent
{
    Task<AgentTurnResult> SendAsync(string userMessage, CancellationToken ct = default);
}

// 5) RAG 检索：把查询转成向量并返回最相关的规范片段
public interface IKnowledgeBase
{
    Task InitializeAsync(CancellationToken ct = default);
    Task<IReadOnlyList<string>> SearchAsync(string query, int topK, CancellationToken ct = default);
}

// 6) Embedding 服务：文本 → 向量
public interface IEmbeddingService
{
    Task<IReadOnlyList<float[]>> EmbedAsync(IReadOnlyList<string> texts, CancellationToken ct = default);
}
```

> 确认以上格式，三个工作流即可并行；后续若需调整接口，务必及时沟通。

## 5. 工具清单（初步确定 5 个，覆盖 读 / 写 / 验证）

| 工具 | 函数名 | 能力 | 复杂度 |
|------|--------|------|:--:|
| 文件浏览 | `list_files` | 递归列出 `.cs` 文件（可通配过滤） | 低 |
| 文件读取 | `read_file` | 读取源码并带行号，便于精确定位 | 低 |
| 静态分析 | `analyze_code` | Roslyn 解析单文件，返回客观发现（空 catch、超长方法、魔法数、`async` 缺 `await`、命名、TODO 等），含行号 | 中 |
| 规范检索 | `search_standards` | RAG 语义检索编码规范，为意见提供依据 | 中 |
| 修改建议 | `propose_fix` | 针对指定问题生成可应用的修改（unified diff / 改写后代码），写入工作副本 | 高 |
| 编译验证 | `compile_check` | 对（修改后）代码做 Roslyn 编译诊断，验证不破坏编译，形成「分析→修复→验证」闭环 | 中高 |

> 6 个函数稳超「≥3」要求；`propose_fix` + `compile_check` 体现「读 → 改 → 验」的真实工程闭环，避免纯只读工具的单薄感。这两个工具也是深度审查「阶段3 修复」中修复 Agent 的主要手段。

## 6. 三人分工

> 原则：均分工作量、最大化并行。

### 组员 A —— 智能体核心引擎（Core：Agent / 记忆 / LLM / 编排 / 提示词）

**任务范围**
- 搭建解决方案骨架、`Core` 类库、DI 容器、配置系统与日志；定义并冻结第 4 节全部公共契约（接口先行，解锁 B、C 并行）。
- LLM 接入层：把 Semantic Kernel 接到 OpenAI 兼容端点，支持配置化的模型 / 端点 / 温度。
- **手写 ReAct 推理循环**（核心评分项）：Thought → Action → Observation 迭代，含 `MaxSteps` 上限、工具调用解析与结果回灌、`FinishReason` 终止判断、每步经 `IAgentObserver` 上报。
- 记忆机制：`IConversationMemory` 实现，含超预算时的摘要压缩（非粗暴截断）。
- **对话式编排 Agent**（系统唯一入口）：挂载工具箱（细粒度工具 + 粗粒度动作）+ 记忆，处理多轮交互，由 LLM 动态决定每一步。
- **多 Agent 深度审查编排（三阶段）**：阶段1 风格/安全/性能专家并行（`Task.WhenAll`）；阶段2 主审汇总；阶段3 修复 Agent（取已确认发现 → 调 `propose_fix` → 调 `compile_check` 验证）。封装为 `run_deep_review` / `run_remediation` 两个粗粒度动作供对话 Agent 调用。
- **全部 system prompt**：对话 Agent、风格 / 安全 / 性能专家、主审、修复 Agent 的提示词（与编排同属一人，便于统一调参与讲解）。

**预期技术路线**
- SK `Kernel` + `OpenAIClient`（自定义 `Endpoint` 指向兼容端点），用 SK 的**手动函数调用**模式驱动循环，不被高层黑盒掩盖五步。
- 五个角色 Agent 复用同一 `ReActAgent` 实现，仅 system prompt 与挂载工具不同。
- 并行期：对照「工具清单契约」用**桩工具**占位（空壳 `[KernelFunction]` 返回固定示例数据），即可独立构建并单测循环机制，不依赖 B 的真实工具。

**需新建/负责的文件位置**
- `src/CodeReviewAgent.Core/CodeReviewAgent.Core.csproj`、`DependencyInjection.cs`
- `Core/Configuration/AgentConfig.cs`、`Core/Configuration/DirectoryLocator.cs`
- `Core/Abstractions/IAgentObserver.cs`、`NullAgentObserver.cs`、以及第 4 节其余接口
- `Core/Llm/KernelFactory.cs`
- `Core/Agent/ReActAgent.cs`、`Core/Agent/AgentResult.cs`
- `Core/Memory/ConversationMemory.cs`
- `Core/Orchestration/ReviewOrchestrator.cs`、`ReviewResult.cs`、`ReviewPrompts.cs`

**预期成果**：可独立单测的核心库；给定工具集即可跑通「多轮对话 + 触发深度审查 + 触发修复」；ReAct 循环可逐行讲解。

### 组员 B —— 工具与知识（Tools / RAG / 语料）

**任务范围**
- 实现第 5 节全部 **6 个工具函数**（面向 A 冻结的工具契约：类带 `[KernelFunction]`，构造签名 `(string rootDirectory[, 依赖服务])`）：
  - `list_files` / `read_file`（文件系统插件，沙箱绑定根目录，防目录穿越）。
  - `analyze_code`（Roslyn 静态分析，输出结构化发现：空 catch / 超长方法 / 魔法数 / `async` 缺 `await` / 命名 / TODO，含行号）。
  - `propose_fix`（生成 unified diff 或改写后代码并写入工作副本；安全护栏：仅限根目录内、备份可回滚）。
  - `compile_check`（Roslyn 把源码编译为内存程序集，返回编译诊断）。
  - `search_standards`（调用 `IKnowledgeBase` 做 RAG 检索）。
- **RAG 子系统**：`IEmbeddingService`（HTTP 调用 embedding 端点，文本→向量）+ `IKnowledgeBase`（语料分块、向量化、余弦相似度 TopK 检索）。
- **知识库语料**：编写 5–6 篇主题分明的编码规范（命名 / 异常与资源 / 异步 / 安全 / 性能 / SOLID），确保不同查询命中不同文档。

**预期技术路线**
- 静态分析：Roslyn `CSharpSyntaxTree.ParseText` 遍历语法树取诊断；`compile_check` 用 `CSharpCompilation` 编译到内存取 `GetDiagnostics()`。
- RAG：规模小，用内存向量列表 + 余弦相似度即可（无需外部向量库）；如需额外加分可接 Qdrant。embedding 默认复用对话端点的同一 Key。
- 全部工具可脱离 Agent 独立单测（直接 `new` 出来传入临时目录与样例代码断言输出）。

**需新建/负责的文件位置**
- `Core/Tools/FileSystemPlugin.cs`、`RoslynAnalysisPlugin.cs`、`CodingStandardsPlugin.cs`、`FixPlugin.cs`、`CompileCheckPlugin.cs`
- `Core/Rag/IEmbeddingService.cs`、`EmbeddingService.cs`、`IKnowledgeBase.cs`、`KnowledgeBase.cs`
- `knowledge/*.md`（语料）

**预期成果**：6 个可单测的工具；一个 Key 即可跑通对话 + RAG；语料检索命中可见区分度。

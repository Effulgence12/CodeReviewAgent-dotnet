# CodeReviewAgent · 部署文档

> 本文档随**发布版本**一起交付，说明如何在一台干净机器上部署并运行本系统。
> 发布形态：**框架依赖（framework-dependent）+ Release**。目标机需预装 .NET 8 运行时；无需源码、无需编译，解压后即可运行。

> **构建信息**：目标框架 `net8.0`；发布命令 `dotnet publish -c Release`（框架依赖，未内置运行时，故体积小、需目标机装运行时）；
> 已在 Windows 11 + ASP.NET Core Runtime 8.0 上验证三个入口均可启动。如需「免装运行时、单文件」形态，可改用
> `dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true`（体积更大，本课程演示采用框架依赖即可）。

## 1. 交付物与目录结构

发布包（`CodeReviewAgent-release.zip`）解压后结构如下，三个入口各自独立、可单独运行：

```
CodeReviewAgent-release/
├─ web/        Web 工作台（面向人的主界面，浏览器访问）
│   ├─ CodeReviewAgent.Web.dll / .exe
│   ├─ appsettings.json                  非机密默认配置
│   ├─ appsettings.Local.json.example    机密配置模板（需复制后填 Key）
│   ├─ wwwroot/                           前端静态资源
│   └─ （其余依赖 dll、.runtimeconfig.json、.deps.json）
├─ console/    命令行对话入口（端到端演示 / 自测）
│   └─ CodeReviewAgent.Console.dll / .exe + 配置 + 依赖
├─ mcp/        MCP stdio 服务端（对外暴露能力给其它 AI 客户端）
│   └─ CodeReviewAgent.Mcp.dll / .exe + 配置 + 依赖
├─ knowledge/  RAG 规范语料（async/exceptions/naming/performance/security/solid）
├─ samples/    含缺陷的示例代码（演示用）
└─ 部署文档.md  本文件
```

> 说明：`knowledge/` 与 `samples/` 是运行时用到的数据目录，程序通过向上查找定位它们，请保持与三个入口目录的相对位置不变（即都在 `CodeReviewAgent-release/` 下）。

## 2. 运行环境前提

| 项 | 要求 |
|---|---|
| 操作系统 | Windows / Linux / macOS 均可（本说明以 Windows 为主，命令在其它系统等价） |
| 运行时 | **ASP.NET Core Runtime 8.0**（务必装这一个——它同时包含基础 .NET 运行时，Web 必需，Console/MCP 也够用） |
| 网络 | 能访问所配置的 LLM / Embedding 端点（如 DashScope / DeepSeek / 本地 Ollama） |
| 可选 | Node.js 18+（仅当用 MCP Inspector 验证 MCP 服务时需要） |

下载运行时：<https://dotnet.microsoft.com/download/dotnet/8.0> → 选 **ASP.NET Core Runtime 8.0.x**。
验证安装：

```powershell
dotnet --info        # 应能看到 .NET 8 与 Microsoft.AspNetCore.App 8.0
```

## 3. 配置 API Key（运行前必做）

本系统所有推理由**真实大模型**驱动，**缺 Key 会显式报错、绝不伪造数据**。每个要运行的入口都需要一份本目录下的机密配置（`appsettings.Local.json`），或使用环境变量。

**方式 A · 配置文件（推荐，逐个入口操作）**

```powershell
# 以 web 为例，console / mcp 同理
copy web\appsettings.Local.json.example web\appsettings.Local.json
# 然后用编辑器打开 web\appsettings.Local.json，把占位串改成真实值
```

`appsettings.Local.json` 内容示例（按你的模型服务填写）：

```json
{
  "Llm": {
    "Endpoint": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "ApiKey": "在此填入你的真实Key",
    "ChatModel": "glm-5.2"
  },
  "Embedding": {
    "Model": "text-embedding-v3"
  }
}
```

> `Embedding` 留空时会自动复用 `Llm` 的端点与 Key（一个 Key 同时驱动对话与 RAG）。

**方式 B · 环境变量（适合容器 / CI，优先级最高，无需文件）**

```powershell
$env:Llm__ApiKey  = "在此填入你的真实Key"
$env:Llm__Endpoint = "https://dashscope.aliyuncs.com/compatible-mode/v1"
$env:Llm__ChatModel = "glm-5.2"
```

> 配置优先级：`appsettings.json`（默认值）< `appsettings.Local.json`（机密）< 环境变量。
> **安全提醒**：`appsettings.Local.json` 含机密，切勿提交版本库或随发布包二次分发。

## 4. 启动各入口

发布为框架依赖形态，统一用 `dotnet <程序>.dll` 启动；Windows 上也可直接双击/运行同名 `.exe`。

### 4.1 Web 工作台（主界面）

```powershell
cd web
dotnet CodeReviewAgent.Web.dll --urls http://localhost:8080
# 或：.\CodeReviewAgent.Web.exe --urls http://localhost:8080
```

启动后浏览器访问 `http://localhost:8080`。

- 用「上传副本」提交 `.cs` 文件（写入隔离会话目录，绝不动原文件），或「使用目录」原地审查本机目录；
- 右侧实时显示推理轨迹（Thought / Action / Observation）；
- 默认对外部目录**只读**；开启「允许修改当前目录」后，Agent 只生成**待确认 diff**，用户确认后才写入并自动建 `.bak`，支持回滚与编译验证。
- 改端口：替换 `--urls` 的端口号；对外网开放用 `http://0.0.0.0:端口`。

### 4.2 Console 命令行（演示 / 自测）

```powershell
cd console
dotnet CodeReviewAgent.Console.dll -- ..\samples     # 参数为审查目录，缺省为 samples
```

启动后直接输入自然语言，例如：

```
列出文件并分析 OrderService.cs 有哪些问题
全面审查一遍这个项目          # 触发风格/安全/性能三专家并行深度审查
把空 catch 问题修掉并验证能编译   # 触发改代码 + 编译验证，并显示新旧 diff
```

输入 `exit` 退出。

> **Windows 终端中文输入**：若用 VSCode 集成终端运行，中文可能乱码（ConPTY 代码页限制）。先执行 `chcp 65001` 再启动即可；Windows 系统自带终端（conhost）无需此步。

### 4.3 MCP 服务端（对外标准接口）

MCP 是 stdio 服务，直接运行后等待客户端经标准输入输出通信（stdout 是 JSON-RPC 通道，日志走 stderr）：

```powershell
cd mcp
dotnet CodeReviewAgent.Mcp.dll
```

用官方 Inspector 自包含验证（需 Node.js）：

```powershell
npx @modelcontextprotocol/inspector dotnet CodeReviewAgent.Mcp.dll
```

暴露两个工具：`analyze_csharp`（纯 Roslyn 分析，不需 LLM）、`review_directory`（多 Agent 深度审查，需 Key）。

## 6. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动报「未配置 LLM ApiKey」 | 正常的安全行为——按 §3 配置 Key 后重试 |
| Web 端口被占用 | 换 `--urls` 端口，或释放占用进程 |
| 深度审查卡顿 / `EOF` / 超时 | 多为网络到模型端点慢；系统已内置 RAG 分批并行 + 重试 + 30s 超时缓解，必要时改用更近的端点 |
| Console 中文输入乱码（VSCode 终端） | 先 `chcp 65001` 再启动；或改用系统自带终端 |
| MCP 客户端连不上 | 确认以 stdio 方式拉起进程；不要把日志写到 stdout（本服务已走 stderr） |
| 提示找不到 `knowledge/` | 保持解压后的目录结构不变（`knowledge/` 与三入口同在发布根下） |

## 7. 生产部署加固（可选）

课程演示环境可用默认配置；若部署到多人/共享环境，建议收紧目录访问策略（Web 与 MCP 共用同一份 `ReviewAccess`）：

```json
"ReviewAccess": {
  "AllowArbitraryDirectories": false,
  "SharedRoots": ["/srv/reviews"]
}
```

`false` 时只允许审查列出的可信根目录，防止越权读写任意路径。
